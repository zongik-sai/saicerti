# 심화 문제 제작 안내 (작업자용) — [심화] 1~5

선생님 요청(2026-11-27): 유형마다 기존 5문제는 **[기본] 1~5**로 그대로 두고, 옆에 **[심화] 1~5**를 더한다. 심화는 **필수가 아니고**, 그 유형의 기본 5문제를 모두 푼 학생이 잠금을 풀고 도전한다. 심화는 1 → 5로 **점점 어려워지고**, 어려운 만큼 **중간 점검을 늘려 앞에서부터 충분히 디딤돌(스캐폴딩)을 놓는다**.

먼저 읽을 것: `docs/CONTENT_SCHEMA.md`(데이터 형식), `docs/AGENT_BRIEF.md`(연습 문제 규칙). C 과정이면 `docs/AGENT_BRIEF_C.md`도. 같은 유형의 기본 문제 파일 `src/content/<과정>/tNN.json`을 **꼭 읽고** 형식·핵심 기술·중간 점검 흐름을 본보기로 삼는다(원본 기출을 다시 볼 필요는 없지만, 핵심 기술을 정확히 알고 싶으면 AGENT_BRIEF에 적힌 원본을 봐도 된다).

## 파일

- `src/content/<과정>/adv/tNN.json` — 머리(`course`, `type`, `kind`, C면 `lang: "c"`)는 기본 파일과 같게. **`typeTitle`은 기본 파일과 글자까지 똑같이**, `kind`도 같게(검수 도구가 확인).
- `skills`: 심화에서 더 쓰는 기술까지. `intro`: 2~3문장, 기본보다 무엇이 더 어려운지(예: "동점 규칙과 빈 결과까지 처리해요").
- 문제 5개, id `<과정>-tNN-adv1` ~ `-adv5`(진도 키라 바꾸지 않음), `version: 1`.

## 난이도 사다리(1 → 5)

| 번호 | 수준 | 중간 점검 |
|---|---|---|
| 심화 1 | 기본 5번보다 한 단계 어려움(조건 하나 추가, 경계 처리) | 6단계 |
| 심화 2 | 조건·경우가 둘 이상 얽힘 | 6~7단계 |
| 심화 3 | 두 가지 기술을 함께(예: 누적 + 정렬 기준, 보조 함수 2개) | 7단계 |
| 심화 4 | 동점·빈 결과·음수 같은 예외 규칙까지 | 7~8단계 |
| 심화 5 | 이 유형에서 가장 어려운 수준(과정별 상한 아래 표) | 8~9단계 |

어렵게 만드는 방법: 지켜야 할 규칙(동점, 같은 값, 없을 때 반환값) 추가, 반복의 단계 수 늘리기(이중 반복, 두 번 훑기), 기술 두 개 결합, 입력 범위 넓히기(음수·0·빈 문자열 허용), 코드가 길어지고 보조 함수가 늘어남. **유형의 핵심 기술은 그대로**(같은 유형의 심화여야 한다).
- blank: 빈칸 수를 기본보다 조금 늘린다(심화 1은 3~4개, 심화 5는 5~8개). 빈칸은 조건식·인덱스·누적식·반환값·함수 호출 같은 핵심 자리.
- fix: 고칠 줄은 **여전히 정확히 한 줄**. 같은 종류의 버그를 더 긴 코드·보조 함수 속·덜 눈에 띄는 곳에 둔다. 다른 한 줄을 고쳐도 통과하는 길이 없게, 틀린 코드는 예시에서 틀리게(무한 반복·오류로 멈추는 버그는 피함).
- write: 틀(함수 머리, `answer = …`, `return answer`)만 준다. 규칙이 많아지는 만큼 예시를 3개 두어 규칙마다 보이게.

과정별 상한(심화 5):
- **pyb**(COS Pro 2급 Python): 2급에서 배우는 문법(반복·조건·리스트·문자열·함수, `len`·`sum`·`max`·`min`·`sorted`·`abs`·`range`·`int`·`str`)만으로 풀 수 있게. 논리는 1급 쉬운 문제 수준까지.
- **pya**(COS Pro 1급 Python): 1급 범위(정렬 기준 `key`/`lambda`, 슬라이싱, 딕셔너리, 보조 함수, 시뮬레이션). 1급 어려운 문제 수준까지. `import`는 쓰지 않는다(필요하면 `math`만).
- **cb**(COS Pro 2급 C): `docs/AGENT_BRIEF_C.md`의 C 규칙 그대로(main 없음, ASCII만, `cspec`, gcc 대조). 논리는 1급 C 쉬운 문제 수준까지. 배열 길이는 숨긴 길이 매개변수로.

## 중간 점검: 앞에서부터 온전한 디딤돌

심화 문제는 어려우므로, 학생이 **중간 점검만 차례로 풀면 코드를 쓸 준비가 다 되도록** 단계를 늘린다. 문제마다 그 문제의 어려운 곳에 맞춰 단계를 짠다(모든 문제에 같은 틀을 복사하지 않는다). 권장 흐름:

1. **문제 이해**(mcq): 핵심 규칙을 정확히 읽었는지. 처음 나오는 말은 해설에서 쉽게 풀어 준다.
2. **규칙 확인**(mcq·short): 경계·동점·예외 규칙을 아주 작은 입력으로 확인.
3. **문제 쪼개기**(mcq): 어떤 순서의 작은 일로 나누는지, 어떤 변수(누적값, 최댓값, 위치 등)가 필요한지.
4. **손으로 따라가기 1**(table): 작은 입력이나 예시 1의 앞부분, 반복마다 변수 값.
5. **손으로 따라가기 2**(table): 두 번째 단계(보조 함수, 두 번째 반복, 동점 처리 등)나 예시 2.
6. **핵심 코드 결정**(mcq·short): 조건식·인덱스 범위·누적식·초깃값·반환값 중 이 문제에서 틀리기 쉬운 곳. **코드 조각을 질문에 직접 적는다**.
7. (심화 3~) **틀리기 쉬운 곳**(mcq·short): 흔한 실수를 하면 어떤 값이 나오는지.
8. (심화 4~) **경계 사례 결과 예측**(short): 빈 결과·동점·최솟값 입력의 반환값.
9. (심화 5) **전체 정리**(mcq·table): 전체 흐름 순서나 다른 예시의 최종 결과.

- 6~9단계, **표(table) 2개 이상·객관식(mcq) 2개 이상**(검수 도구가 확인).
- 질문·보기·해설에 빈칸 번호(⟦1⟧ 등)를 쓰지 않는다(검수 도구가 막음). 코드를 보지 않고 질문만 읽어도 풀리게.
- 코드 정답을 빈칸마다 그대로 알려 주지 않는다. 대신 **그 답을 스스로 떠올리게 하는 질문**(이 조건이 참이 되려면? 마지막 칸의 인덱스는?)을 둔다.
- 앞 단계가 다음 단계의 디딤돌이 되게: 앞에서 확인한 규칙·값을 뒤 단계가 쓴다.
- 해설은 2~4문장, 왜 그런지까지. 표 정답은 `check`의 `answers()`가 계산(가능하면 정답 함수를 그대로 실행).
- 말투: 문제 문장은 합니다체, 중간 점검·해설은 해요체.

## 그 밖의 규칙

- 상황(이야기)은 새로: 같은 유형의 **기본 5문제와도, 심화 5문제끼리도** 겹치지 않게. 제목도 서로 다르게(2~30자).

- `inputCheck`는 매개변수 설명의 조건을 그대로. 예시 설명은 값과 정확히 맞게.

- `python3 tools/validate.py src/content/<과정>/adv/tNN.json` 이 `✓ 문제 5개 검수 통과`가 될 때까지 고친다.
